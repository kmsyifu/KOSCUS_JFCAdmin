Release Note - KOSCUS_JFCADMIN018 (11/04/2026)   Branch: version-2.3
Order Detail (Common/OrderDtl.ascx, OrderDtl.ascx.vb): edit price in the list with live GP, better Add Item panel.
Short version is in ReleaseNotes.txt. Version 017 details are in ReleaseNote_JFCADMIN017.txt.
----------------------------------------------------------------------------------------------------------------------------------

Before
  1. Edit on a row loaded the item into the "Add Item to Order" panel and opened the Set Price popup.
  2. OK only changed the price shown in the panel - nothing was saved. The popup said "please click Update".
  3. The user then had to click the panel's Update button (saves price + qty), then Update Order (email / status).
  4. If Update Order was clicked instead of the panel's Update, the new price was silently lost (Update Order always
     kept the old price).
  5. Adding an item after changing a qty in the list asked "Changes in qty will be lost".


==================================================================================================================================
1. EDIT PRICE IN THE ORDER ITEM LIST
==================================================================================================================================
1.1 Click Edit under the price -> a price box, and under it the unit list (/lb, /cs, /ea - same units as the old
    popup) with a check mark and an X, appear in the row. No popup, no page reload.
    Price box, unit list and check mark / X are stacked and the same width (72px), right-aligned under the price.
    While a new price is set, it is shown in the old price's place (top of the cell), labelled "Updated" ($x/cs, $y/ea, ...);
    the old price is hidden.
    Check mark (or Enter): keeps the new price - the box closes, the "Updated" price stays (Edit reopens it).
    X: cancels the change and shows the old price again.
1.2 While typing (price or qty), JavaScript updates:
      - the row's new prices (= $x/cs, $y/ea, $z/lb), GP % (bold, red if negative) and line amount
      - Total amount (header and bottom line) and Total GP
      - row turns yellow and shows "Below bottom $x/cs" when the case price is below bottom
    This is only a preview. Enter in the price box does not submit the page.
1.3 Update Order saves the qty and the changed prices in the same transaction. The server works out the cs / ea / lb
    prices with Common.SetPrice - the same SQL the old popup used - so prices are calculated exactly as before.
    The bottom price warning (Yes / No) checks the new case price.
1.4 Edit only shows for JFC admins, on JFC items that have a cost (before: on every row).
1.5 A non-number or 0 price gives "Price for item #... has to be a positive number".

==================================================================================================================================
2. ADD ITEM TO ORDER PANEL
==================================================================================================================================
2.1 Set Price opens a price box in the panel with Cost and Bottom shown (was a popup): price box (90px), unit list
    (same size as in the list), green check mark and red X - same as the list.
    While typing, the new price is shown in the current price's place on the Price line, labelled "Updated", with GP and
    Amount. The link is "Edit Price" (was "Set Price").
    Check mark (or Enter) puts the new price in the panel's Price line as "Updated $x / cs ...", closes the box and shows
    "Updated price is set. Click Add to Order / Update to save it." (needed for an item with no price yet, so the qty
    boxes and Add to Order appear). X cancels and shows the current price again.
2.2 GP % and Amount update while typing the price or qty.
2.3 Add to Order / Update uses the typed price even if Apply was not clicked. A below-bottom price is allowed and
    the warning is shown in the success message (same as the old popup).
2.4 GP % shows as soon as a JFC item is loaded (before: always blank until a price was set).
2.5 Item that already has a price: no price step - enter qty and Add to Order. Edit Price is only to change it.
    Item with no price: the price box opens right away (no need to click Edit Price first).

==================================================================================================================================
3. KEEP UNSAVED LIST CHANGES
==================================================================================================================================
3.1 Adding an item or deleting a row reloads the list but keeps qty / prices typed in the other rows (not saved yet -
    Update Order still saves them). The "Changes in qty will be lost" question is gone.

==================================================================================================================================
4. FIXES
==================================================================================================================================
4.1 Price set with Edit was lost when Update Order was clicked (see "Before" 4).
4.2 The Set Price OK code read lbPrice_OrderByWgt from the SetPrice query, which does not return that column.
    It now uses the order-by-weight price already shown in the panel (Set Price does not change it).
4.3 Branch 05 customers never see Each qty (Common.HideEaQty). After setting a price in the Add Item panel, the Each qty
    box and each price came back anyway (the old popup code skipped that check). Now the same check is used.
    Test: branch 05 customer, Add Item, Edit Price + check mark: no Each box; other branch: Each box shows as before.
4.4 Update Order / Approve Order with every qty set to 0: each line with 0 qty is deleted, so the order was saved empty
    (Approve Order also approved it and emailed the customer). The "Order is empty" check only looked at the saved
    order. Now: "All quantities are 0. Please enter qty for at least one item, or use Delete Order to cancel the order."
    Test: set all qty to 0, Update Order -> message, nothing saved.
4.5 Bottom price warning: after "Yes", the bypass flag stayed on if Update Order then stopped on another error (bad qty,
    VP memo, ship date), so the next Update Order skipped the warning even for a new low price. The flag now only
    covers the postback right after "Yes".
    Test: low price -> Update -> Yes with a bad qty -> fix qty -> Update: warning shows again.
4.6 Delete Order / Change Back to Order Placed Status: the order status is checked again when "Yes" is clicked
    (delete only for Order Placed or SFA downloaded; change back only for SFA downloaded). The change-back dialog
    title was "Confirm Cancelation" - now "Confirm Status Change".
4.7 Invoice download from the order closes the database reader before sending the file.
4.8 Add Item to Order search box (autocomplete, item # or keyword) - script at the top of OrderDtl.ascx:
    - The list went empty / stale after the 2nd letter: the plugin filtered the first reply in the browser by
      "starts with", but each row starts with "#item#, description". Now every search asks the server (matchSubset off).
    - An older, slower search could replace the list for the current text (the plugin needs the ajaxQueue plugin to
      cancel old requests and it is not loaded). Now an older search is canceled when a new one starts.
    - Picking an item did not load it; it loaded only when the box got focus again, so clicking back into the box
      reloaded the old item and cleared the qty typed. Now picking an item (click or Enter) loads it right away.
    - Search starts at 2 letters (1 letter matched most of the catalog and was the slowest).
    Test: type part of a description (e.g. 2-3 words), type an item #, pick with mouse and with arrow keys + Enter,
    then click back into the search box (item and qty must stay).
4.10 Enter key went to Login.aspx: when the box had no working default button, the browser used the first submit button
     on the page - the menu's Logout button (JFCAdmin.master, PostBackUrl Login.aspx). Happened in the Order Info boxes
     (ship date, message, PO #, Msg on JETS), in the item list of an Order Placed order (Update Order is hidden there,
     Approve Order shows) and in the Add Item panel for an item with no price (Add to Order hidden).
     Fix: the whole Order Detail is in a panel whose default button does nothing. Enter still runs Get Item,
     Add to Order and Update Order where those buttons show.
     Test: Enter in each Order Info box, in a qty box of a new order and of an approved order (Update Order), in the
     item search and the Add Item qty box - never goes to the login page.
     Same fix on the other pages (JFCAdmin/CustItem, CustSetting, BranchSetting, Tool, OrderForm, Balance, OrderHistory .aspx):
     the page content is in a panel pnlEnterKey whose default button btnEnterNoop does nothing. Boxes inside a panel with
     its own default button (search, save, popups) still run that button.
     Test: on each page press Enter in every kind of box (search, grid, popup) - runs its button or nothing, never logs out.
4.11 AR Balance link (Order Info, JFC admin) works again: opens JFCAdmin/Balance.aspx?customer_id=...&cmd=show_dtl in a new
     tab (that customer selected, payment detail shown). The URL is app-relative (ResolveUrl) - it was built from
     Request.Url, which can be the internal server address behind the proxy. Customer id is URL-encoded.
     Test: open an order, click AR Balance: Balance page opens for the same customer.
4.12 Delete a row (Yes): the order's saved total amount (sohdr.totalAmt, shown in the Order History list) was not
     updated - it kept the old total until Update Order was clicked. Now it is updated with the delete.
     The order status is also checked again at "Yes" (the order may have been approved / downloaded meanwhile).
     Test: delete a row, go back to Order History without Update Order: total is the new amount.
4.13 Row colors (JFC admin): the colors set when the list loads and the colors set again after each click used
     different rules, so a row could change color after any click (e.g. a promo item that is also new: green, then
     blue). Both now use one function (SetRowColor): out of stock pink > below bottom yellow > promo green > new blue.
     A row with no price ($0) is no longer yellow "below bottom". Customer orders are no longer colored after a click
     (they never were when the list loaded).
4.14 Out of stock (pink row, red qty) is only for JFC items. Other items have no stock data (always 0), so every
     non-JFC row showed pink.
4.15 Get Item for an item deleted from the order form: the item reader is closed before the "restore?" question,
     and the dialog title reads "Item Has Been Deleted" (was "Item has been delete").
4.16 Changed price label "New" -> "Updated" (list and Add Item panel, and the "Updated price is set" message).
     "Below bottom $x/cs" stays on one line (was wrapped in the narrow price cell).
4.17 Order Form (JFCAdmin/OrderForm.aspx.vb MatchTagHtml) item search: when a search word is not in the description or
     item ID, the line under the description shows only about 60 characters of text around the match, the word in
     bold. The field name tag before it (Japanese / Long description / Web description / Sales point) is removed.
     Test: Order Form, search a word that is only in the long description: the item shows the text around that word.
4.18 Login page (Login/Login.aspx, Login/Styles/Login.css): eye button inside the right edge of the password box shows /
     hides the password (icon changes to a crossed-out eye). type="button", so Enter still logs in; not in the Tab order.
     Works on the mobile login page too (same page and stylesheet).
     Test: Login page, type a password, click the eye (shown), click again (hidden), press Enter (logs in).
4.19 Order Form (JFCAdmin/OrderForm.aspx.vb): sort by "Selected" lists the selected items first, then by item #
     (was by description). Item # is sorted as text, same as the "Item #" sort.
4.20 Order Form (JFCAdmin/OrderForm.aspx.vb BindItemsGrid): the "no price" check now also looks at lbPrice_orderByWgt,
     so items priced only by weight are listed (before, hidden). Lb Price column (OrderForm.aspx) shows lbPrice_orderByQty,
     else lbPrice_orderByWgt. Same rule as the app order form list (API #91).
     Test: exception group with a weight-priced item: it is listed with its lb price and can be saved on the form.
4.21 Login page show-password eye (4.18): styles moved from Login/Styles/Login.css into Login.aspx. With an old Login.css
     in the browser cache the button and both icons showed full size below the box. Icons have a fixed 20px size;
     Edge's own reveal icon (::-ms-reveal) is hidden so there is only one eye.
     Test: Login page (after a normal refresh, no cache clear): eye is inside the right edge of the password box.
4.9 Item search query (Common/Suggestion.ashx, code=ITEM - used by Order Detail Add Item and Customer Items):
    - Returns only as many rows as the list shows (limit sent by the autocomplete, 30; max 150). Before, every match
      was returned and the list showed 30 - a short search returned most of the catalog.
    - The "item is in more than one order form" count is in the same query, only for the rows returned (was one
      extra COUNT query per row).
    - Item # match ignores case and a leading "#" (the list shows "#123, ..."; typing "#123" found nothing before).
    - Same rows, order and text as before otherwise.
    Test: Order Detail and Customer Items search: "#" + item #, lowercase item #, keyword; an item in two order forms
    still shows the order form name in front.
