KOSCUS_JFCADMIN022 (11/09/2026)
*<Common>: Version changed to 022 (Common.VERSION), so browsers load the new CSS / JS files.
*<DBHelper, Global.asax, Error page>: Fixed: random "ORA-03113: end-of-file on communication channel" errors (e.g. Customer Settings delivery point list). An idle pooled database connection that the server / network had cut was handed to a page; DBHelper retried it, but the pages' SqlDataSource controls (about 28 lists) did not. Now a lost connection (ORA-00028, 01012, 03113, 03114, 03135, 12571) clears the connection pool, anywhere in the site: DBHelper clears it before its retry, and Global.asax clears it for any page and loads the page again once (page open / link; dbretry=1 in the address stops a loop). A postback, or a second failure, shows "The connection to the database was lost. Please try again." instead of the error page. Each case is written to App_Data\ErrorLog.
*<CustSetting, Suggestion.ashx, Global.asax>: Fixed: Add / Register Customer popup showed the whole error page in the customer name when the name lookup failed on the server, and the popup could still be saved. The JFC # name lookup and the sales rep lookup (JHO database link, sometimes cut while idle) now try once more; the email check read the sales rep without Read() (always failed on production / beta) and now reads it properly (no sales rep found: "not assigned"). An error in an AJAX handler (.ashx) now returns a plain HTTP 500 instead of the HTML error page, so pages run their error handling; the popup shows "Could not look up the customer / check the email (server error). Please try again." and cannot be saved.
*<CustItem, Suggestion.ashx>: Fixed: Edit item info - typing a New price showed "Error occured" (ORA-01722: invalid number), and Update with a new price / adding a price inquiry item could fail the same way. SetPrice puts the item # and customer ID into the SQL as they are; these callers passed them unquoted, so Oracle compared the text columns as numbers (fails on non-numeric values such as customer ADMIN). They are now quoted with DB.SqlEsc (Order Detail already did this).
*<CustItem>: Buy Again display order on the full site works like the mobile site: press and hold a row for 1 second (mouse or finger), then drag it up / down (saved when released; the page scrolls near the top / bottom of the window); or click the up / down buttons on each row (saved 1 second after the last click). The instructions and "Saving... / Order saved" show on both sites. A quick click still opens the item link and a quick mouse drag still selects text. Replaces the jQuery UI sortable (one drag code for touch and mouse); the browser's own link / text drag is blocked while a row is held.
*<Popup.css, CustItem, CustSetting, BranchSetting, Balance, ShowItemDtl, Masters>: All popups have the same look as Customer Items - Item Info and Customer Settings - Add New Customer (orange header with a close button, labels above the boxes, red error box, footer with Delete on the left and Close / Update on the right), from the shared Styles/Popup.css (kp-* classes, loaded by both masters): Customer Items - Copy items to another customer and Promo Item; Customer Settings - Delivery; Branch Settings - Promo Item, Order Reminder and Delivery Master; Balance - New Account; Order Detail - Item Info (image beside the details, above them on phones). Control IDs and server code are unchanged; the old image close buttons are now the header close button (same server handlers); empty error messages no longer show an empty box; the Delivery popups do not cut off the date calendar.
*<DBHelper>: Fixed: "Timeout expired. The timeout period elapsed prior to obtaining a connection from the pool ... max pool size was reached" (e.g. on Login). When the connection check after Open (SELECT 1 FROM dual) failed - the last ORA-03113 retry, another Oracle error, or the 60 second query cancel - the new connection was not closed and the constructor threw, so the caller's Using never closed it either; the connection stayed taken until garbage collection, and after some database hiccups the pool was full. Now every failed connect attempt closes its connection before retrying / throwing (lost connection: pool cleared, up to 2 retries as before); the EVENTLOG note after a successful retry cannot fail the connection; Close() can be called twice. To free connections that were already leaked, recycle the application pool.
*<CustItem>: Buy Again display order: the up / down buttons are removed; a new "Order (Hold 1 sec to move)" column before the delete icon shows the same sort icon as Branch Settings - Homepage images (hold a row or the icon 1 second, then drag it). "Change Display Order" is shown only once (full site: hold and drag, or the Excel Export / Import steps; mobile: touch and hold). The "Saving... / Order saved" message is not shown any more (the order is still saved after each drag; only an error is shown).
*<CustItem>: Mobile site: space between the Search Items and Add / Update Item panels; "Category" and its list stay together (on a narrow phone both go to the next line; the list is at most 70% of the screen width).
*<Common, CustSetting, BranchSetting, Login>: Email bodies built in code have the same look as the other emails (EmailBody.ascx): gray page, white card (max 680px) with the orange header bar (company name), table layout with inline styles for Outlook / Gmail / phone mail apps. New helpers in Common: EmailLayout (the card), EmailInfoBox (orange title and label / value rows, values HTML encoded) and EmailLinkButton (orange button link). Changed: "Your delivery info has been updated" (Customer Settings - Delivery and Branch Settings - Delivery Master: Old / New boxes, new values in bold, customer name HTML encoded); one time verification code (code shown large in an orange box, expiry note); "Set your password" (now an HTML email with a Set your password button, the link also shown as text in case the button does not work).
*<CustSetting, DBUpdate>: Customer Settings - when Allow Chat is changed, the customer's jetsDataModDate is set to the current date / time (sysdate). Not changed when Allow Chat stays the same.
*<CustSetting>: Mobile site: in the Users list, the Cell Phone (Text) box is just wide enough for one phone number ((###)###-####) instead of the browser's default width, and its column is no longer 196px wide.
*<Confirm>: One time verification code email: "Please note that this code will expire in 20 minutes." is now inside the code box, under the code. As the last line of the email (the same in every code email) Gmail hid it behind the "..." (trimmed content) button.
*<CustItem, DBUpdate>: Fixed: Copy item info to another customer could fail with "ORA-00001: unique constraint (KOSCUS.JFCCUSTOMERPRICE_PK) violated" when the same item was copied twice at the same time (Copy clicked again while the first copy was running, or two users). The Copy button is now disabled and shows "Copying..." after one click, and the copy save (new DBUpdate.SaveCustItemCopy) rolls back and runs once more on ORA-00001, so it updates the row the other copy saved instead of inserting it again.
*<OrderDtl, Common>: Order Update: a lost database connection (ORA-03113 etc.) while building the update email showed the error page, although the order was already saved and no email was sent. The email is now built with the new Common.TryCreateEmailBody: on a lost connection it clears the connection pools and builds the email once more; if it still fails, the order stays saved and the "Successfully updated, but the email could not be sent ... Please resend the email" warning is shown instead of the error page.
